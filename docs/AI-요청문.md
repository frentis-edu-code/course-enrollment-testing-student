# AI로 테스트 만들고 확인하기

학생 저장소: https://github.com/frentis-edu-code/course-enrollment-testing-student (받기·준비: README)

이번 수업의 복사용 정본입니다. 현재 장표와 같은 새 요청(v5 제안)이며 과거 AI 실행 원문이 아닙니다. 이 요청으로 AI가 실제로 코드를 만들고 시험을 통과했다는 기록은 없습니다. 결과는 각자의 실행에서 확인합니다.

요청은 목적과 대상만 짧게 적었습니다. 테스트를 둘 위치·이름·태그, 바꾸면 안 되는 파일은 공통 준비 요청으로 AI가 [AI 공통 안내](AI-공통-안내.md)를 읽게 해 지킵니다. 아래의 **만들 파일 예시**는 저장소에 아직 없는 파일이며, AI가 다른 이름으로 만들었으면 실제 이름으로 읽습니다. **사람이 볼 것**은 요청에 넣지 않고 결과를 받은 뒤 사람이 확인하는 기준입니다.

실행 후속 요청은 생성된 코드를 먼저 읽은 다음 보냅니다. 성공을 가정한 각본이 아니므로, 그 뒤의 대화는 실제 결과에 따라 달라집니다. AI가 명령을 실행할 수 없는 도구라면 같은 명령을 본인 터미널에서 실행합니다. Java는 프로젝트 루트, 화면 E2E는 `frontend`에서 실행하며 Windows에서는 `./mvnw` 대신 `.\mvnw.cmd`를 씁니다.


사람이 볼 것: 정리에 practice와 frontend/e2e의 위치, 앱·support·요구 문서·설정을 바꾸지 않는다는 조건, templates는 참고용이라는 점이 들어 있는가. 빠졌으면 그 부분을 다시 읽게 합니다.

## 4. 실습 3: AI 요청과 단위 테스트 검토·실행 — 67쪽

```text
docs/requirements.md의 정원 규칙과 EnrollmentRules.java를 보고, 정원이 찼을 때 추가 신청을 막는 단위 테스트를 만들어 줘.
한 자리 남았을 때와 다 찼을 때를 비교해 줘.
기존 앱 코드는 바꾸지 말고, 만든 테스트가 무엇을 확인하는지 설명해 줘.
```

만들 파일 예시(아직 없음): `src/test/java/com/example/enrollment/practice/RulesCapacityTest.java`

생성된 코드를 읽은 뒤 보내는 실행 후속 요청:

```text
방금 만든 테스트를 실행하고, 실패하면 원인을 설명해 줘.
```

직접 실행할 때: `./mvnw test -Dgroups=unit` (이 파일만: `./mvnw test -Dtest=RulesCapacityTest`, 이름이 다르면 실제 클래스 이름으로 바꿈)

사람이 볼 것: practice 아래 새 테스트만 생겼는가 / 정원 20에 신청 인원 19명은 접수, 20명은 `COURSE_FULL`인가 / 예상값이 요구 문서의 정원 규칙에서 왔는가 / 실제 출력의 신규 테스트 이름·실행 수(0 아님)·실패·건너뜀 / 부족한 방향(경계·예외·조합) 하나만 이유와 함께 보강 요청, 충분하면 유지

## 5. TDD 실습: 취소 기한을 실패 테스트부터 구현하기 — 70쪽

```text
취소 기한 판단을 TDD로 연습하자. docs/requirements.md의 취소 기한 규칙을 보고, 시작 24시간 전 정각과 1초 뒤를 비교하는 실패 테스트부터 만들어 줘.
판단 코드는 기존 앱이 아니라 연습용 새 클래스로 두고, 테스트를 만든 뒤 멈춰 줘.
```

만들 파일 예시(아직 없음): practice의 `CancellationDeadline.java`(연습용 판단 클래스)와 `CancellationDeadlineTest.java`

생성된 코드를 읽은 뒤 보내는 실행 후속 요청:

```text
방금 만든 테스트를 실행하고, 의도한 이유로 실패했는지 설명해 줘.
```

직접 실행할 때: `./mvnw test -Dgroups=unit` (이 파일만: `./mvnw test -Dtest=CancellationDeadlineTest`, 이름이 다르면 실제 이름으로 바꿈)

사람이 볼 것: 빨강 — 신규 테스트가 기능이 아직 없어서 실패했는가(컴파일 오류·환경 오류·미작성 `fail`은 이번 빨강이 아님) / 초록 — 테스트는 그대로 두고 최소 구현만 요청한 뒤 같은 실행 / 정리 — 동작을 바꾸지 않는 정리 뒤 같은 실행으로 재통과 / `src/main` 불변 / 미완료면 새 연습 파일만 프로젝트 밖에 보관하고 작업 폴더에서 제거·기록

따라 하기: 같은 파일에 "이미 신청한 과정에 같은 사원이 다시 신청" 테스트를 더해 달라고 요청하고, 409 `DUPLICATE_ENROLLMENT`와 신청 인원 그대로를 확인합니다.
