# 실습 3. 단위 테스트 보강과 결함 기록

AI로 테스트 코드 초안을 만들 때의 첫 요청(복사해 쓰고, 필요하면 고쳐 씁니다)

구현 본문(`EnrollmentRules.java`의 메서드 안쪽)은 붙여 넣지 않습니다. 예상값을 구현에서 베끼지 않고 규칙 문서에서 가져오게 하기 위해서입니다. 대신 아래의 호출 방법만 줍니다.

```
아래는 교육 과정 신청의 규칙 판단 객체 EnrollmentRules의 호출 방법과 규칙 문서다.
- new EnrollmentRules().checkEnrollment(EnrollmentCheck) 는 Optional<ErrorCode>를 돌려준다. 거절 사유가 없으면 빈 값이다.
- EnrollmentCheck(요청 시각 LocalDateTime, 신청 마감 일시 LocalDateTime, 같은 과정에 신청됨 신청이 있는가 boolean,
  사원의 보유 신청 수 long, 과정의 신청 인원 long, 정원 int)
- ErrorCode 값: ENROLLMENT_CLOSED, DUPLICATE_ENROLLMENT, ENROLLMENT_LIMIT, COURSE_FULL
[docs/requirements.md 3절을 붙여 넣기]

JUnit 5와 AssertJ로 개인 한도 규칙 R5의 단위 테스트를 작성해 줘.
- 각 테스트의 이름에 확인하는 조건을 적고, 예상값의 근거 규칙을 주석으로 달아 줘.
- 예상값은 규칙 문서에서 가져와 줘.
- Spring이나 저장소 없이 new EnrollmentRules()로 시험해 줘.
```
