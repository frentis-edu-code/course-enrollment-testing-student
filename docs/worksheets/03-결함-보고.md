# 실습 3. 단위 테스트 검토와 실패 원인 기록 — 선택 기록 양식

> 필수 양식이 아닙니다. AI에 요청하기 전에 채우지 않으며, 기록이 필요할 때만 씁니다. 요청문은 [AI 요청문](../AI-요청문.md)의 “실습 3: AI 요청과 단위 테스트 검토·실행”과 “TDD 실습: 취소 기한을 실패 테스트부터 구현하기”를 복사해 씁니다. 순서와 TDD 완료 조건은 [실습 진행 안내](../실습-진행-안내.md)를 따릅니다. 이전 수업의 원래 양식은 `templates/history/worksheets-original/`에 그대로 보존되어 있습니다.

## 수업 흐름

1. 정원 규칙 단위 테스트: AI가 `docs/requirements.md`의 정원 규칙과 `src/main/java/com/example/enrollment/rules/EnrollmentRules.java`를 보고 practice에 새 테스트를 만듭니다. 만들 파일 예시는 `RulesCapacityTest.java`이며 아직 없는 파일입니다.
2. 생성된 코드를 읽은 뒤 실행 후속 요청으로 실행합니다. 직접 실행할 때는 프로젝트 루트에서 `./mvnw test -Dgroups=unit`입니다.
3. TDD: 취소 기한 규칙으로 실패 테스트부터 만들고(예: `CancellationDeadline.java`·`CancellationDeadlineTest.java`, 아직 없는 파일), 빨강·초록·정리마다 같은 실행을 합니다.

TDD의 빨강은 연습 기능이 아직 없어 검증이 실패한 경우만 해당합니다. 컴파일 오류, 환경 오류, 미작성 `fail`과 구분합니다. 이 실습에서 앱 결함 수정은 필수 과제가 아니며, 앱 결함이 의심되면 근거와 수정 범위를 먼저 강사와 확인합니다.
